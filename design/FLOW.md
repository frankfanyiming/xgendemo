# FLOW —— 产品流程与页面 v1

> 上承 `HARNESS.md`（硬约束）与 `SOUL.day1.md`（出场设置）。本文件只管**用户看到什么、按什么顺序**。
>
> **载体假设：微信小程序。** 核心流程与载体无关；受载体影响的只有四处，文中标注 ⚑。

---

## 一、召唤 · Onboarding

**这是整个产品成败的地方。** 用户对守护神的全部判断在这 90 秒内形成，且只有一次机会。

**唯一目标：90 秒内让他看到首读，并且被说中。**

```
① 落地      → ② 报生辰 → ③ 排盘（等待）→ ④ 首读·上半
                                              ↓
⑦ 第一句对话 ← ⑥ 首读·下半 ← ⑤ 显形选择 ←────┘
```

### ① 落地页

- 一句话说清它是什么，**不解释产品，直接给一个动作**："报出你的出生时刻，看看会出现什么"
- **不注册、不登录、不要手机号**。注册留到第 ⑦ 步之后
- 不放功能列表、不放"三大特色"

### ② 报生辰

三个字段：**出生日期 · 出生时刻 · 出生地**。

**最大的坑：很多人不知道自己的出生时辰。** 这是真实的转化杀手，必须正面设计：

- 时刻选择器里给一个明显的 **「不确定」** 选项，不要让人卡在这
- 选了不确定 → 用**日柱主导**（日主不依赖时辰，性格底色照样能推）
- 诚实告诉他：「不知道也能算，知道的话我能更准。以后想起来随时补」
- ⚑ 出生地：小程序可用城市选择器，不要做地图选点

**信任前置**：这一页底部要有一句关于隐私的实话——生辰用来做什么、存在哪、能不能删。**这是用户第一次交出私密信息的时刻，一句诚实的说明胜过任何 slogan。**

### ③ 排盘（等待 10–15 秒）

**这是仪式，不是 loading。** 但也不要超过 15 秒。

- 逐步显示推演过程：四柱 → 日主 → 月令 → 喜用神。让他看见"这是有根据的"，而不是随机生成
- 不要做转圈进度条，不要做粒子特效
- 结束时不弹"生成成功"，直接进入首读

### ④ 首读 · 上半（钩子）

**它开口的第一句话。整个产品最重要的一屏。**

- **必须硬**：准、有穿透力，说得他愣一下。别谦虚、别自嘲、**别加"仅供参考"**
- 说**性格与处境**，不说预测（"你这两天容易内耗，少揽事"，不是"你明年会发财"）
- 长度控制在能一屏读完
- **不给按钮**。读完自然往下走

> 设计判据：这一屏如果不能让人截图发朋友圈，onboarding 就是失败的。

### ⑤ 显形选择（插在首读中间，这是刻意的）

它说完第一段，问一句：**「那我该以什么样子出现？」**

- 从同一张盘推出 **2–3 个候选**，用大白话："一盏灯" / "一只夜里的鸟" / "一只黑狐狸"
- **绝不硬映射**（怕狗的抽到犬、巳时的抽到蛇、回族用户抽到猪 —— 都是事故）
- **选完锁定，不可更换**。稀缺感保留在选择之后
- 选完可以赐名，也可以先用它的默认名，**随时能改**

> **为什么插在中间**：首读是钩子，必须最快到达——用户被打动之前不会在意它长什么样。
> 先给价值再要投入；而"被说中"之后亲手选它的样子，这个选择本身成了对关系的确认。

### ⑥ 首读 · 下半

- 接着讲：**它自己**（同一张盘 → 它和你一副线路，有一样的毛病）
- 这里第一次露出"同辰"：不是高你一等的神，是同一时刻生出来的另一个
- 一句话交代它怎么活：「我对你的了解全靠你跟我说」

### ⑦ 第一句对话

**不能冷场。** 它必须主动问一个问题，而且按 SOUL 规则：**问只有他能答的**（经历、感受），不问观点题。

- ✓ "你今天过得怎么样"太空 → 改成具体的："刚才那段里哪句最不对？" 或 "你最近在烦什么事"
- 用户回了第一句之后 → **才引导注册**（"想让我记住这些，得知道怎么找到你"）

⚑ 注册即微信授权，一步完成。

## 二、日常

### 主界面 = 对话

不要做成有五个 tab 的 app。**主界面就是跟它说话**，其余全部收起来。

### 形态与空间（最小可行版）

Day 1 不做复杂的成长动画。最小可行的"活着"信号只有三样：

| 元素 | 内容 | 注意 |
|---|---|---|
| 形象 | 用户选定的那个样子，有细微的状态变化（醒着 / 安静） | 不做等级、不做进度条 |
| 它今天在干嘛 | 一句它自己写的状态 | 必须来自真实日记，不能是随机文案 |
| 认识多少天 | 累计天数 | ⚠️ **不是连续天数** |

> ⚠️ **红线**：认识天数是**累计事实**（断了不清零），不是 streak。
> 一旦做成连续打卡，就违反 HARNESS L4「禁止依赖工程」。**断掉不能有任何惩罚或提示。**

### 主动消息

⚑ 小程序的推送能力受限（订阅消息需用户逐次授权），这是选小程序的**最大代价**，需要在产品上绕：
- 服务通知走订阅消息，且**只在真有事时用掉一次配额**——正好和 SOUL「没话就别说话」一致
- 用户回来时，未读的主动消息按时间自然呈现在对话流里，不做红点轰炸

### 禁止清单（对应 HARNESS L4）

- ✗ 连续打卡 / 签到 / streak
- ✗ "它想你了""你已经 3 天没来看它" 这类内疚话术
- ✗ 未读红点堆积制造焦虑
- ✗ 任何形式的社交积分、勋章、等级、排行榜

## 三、引荐（v2，有第二个用户之后）

### 引荐卡片

- **会过期**（24 小时）。稀缺但不制造焦虑——过期就没了，**不做"你错过了"的提示**
- 卡片内容：**它用自己的话说为什么是这个人**（两三句，可以讲两张盘的合缘，但不上命理课）+ 对方的窄接口信息（气质标签、开放话题）
- **绝不展示对方的私密内容**（HARNESS L2：只传 `GuardianShareCard`）
- 两个按钮：**认识一下** / **这次算了**。选"算了"不需要理由，也不追问

### 双边同意 → 建房

两边都点了"认识一下"才建房。**任何一方没点，另一方不会知道曾经有过这张卡**（避免尴尬和面子成本）。

### 四方房间

- 成员：两个真人 + 两只守护神
- 守护神开场：像朋友介绍朋友，抛一个双方都接得住的具体话题
- 他们聊起来 → 守护神闭嘴
- 冷场 → 救场（点名、递话、问只有对方能答的）
- **agent 的每条消息必须指向一个真人**，不许互相搭腔
- 连续 3 次救场无回应 → 体面收尾

### 房间结束

- **成功的样子是他们迁出去**（加微信、约见面）。产品要**主动提供这个出口**，不要试图把人留在房间里
- 结束后各自的守护神跟主人复盘一句，不做评分表

## 五、关键决策与理由

| 决策 | 理由 |
|---|---|
| 注册放在第一次对话之后 | 先给价值再要身份。onboarding 每加一步登录，流失一大截 |
| 显形选择插在首读中间 | 先给价值再要投入；选择成为对关系的确认 |
| 不确定时辰必须支持 | 中国人大量不知道出生时刻，卡在这直接损失一半用户 |
| 排盘过程可见 | "有根据"是信任的一部分，不能像随机抽卡 |
| 认识天数 ≠ 连续天数 | 一字之差，一边是陪伴，一边是 HARNESS 明令禁止的依赖工程 |
| 引荐卡片会过期但不提示错过 | 稀缺感要，焦虑不要 |
| 单方拒绝对方不可见 | 消除面子成本，这是引荐敢不敢点的关键 |
| 房间主动提供迁出口 | 我们的成功指标就是他们去站外继续 |

## 六、v1 明确不做

- 引荐与四方房间（没有第二个用户）
- 形态成长动画、专属空间可视化（先验证留存，再做重资产）
- 语音、图片生成、角色立绘
- 社群、广场、动态流 —— **一旦有广场，产品就变成另一个社交 App，守护神就没用了**
- 任何积分 / 等级 / 打卡

> **v1 只需成立一件事**：一个人报了生辰，被第一读说中了，第二天还愿意回来跟它说话。
> 这件事不成立，引荐、匹配、网络效应全都不成立。
