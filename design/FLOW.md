# FLOW —— 产品流程与页面 v2.1

> 上承 `HARNESS.md`（硬约束）与 `SOUL.day1.md`（出场设置），下接 `../app/`（已实现）。
> **v2 相对 v1 的根本改动**：删掉了七屏向导。整个产品只有两个页面，召唤发生在对话里。

---

## 零、两条统领全局的规则

**① 产品的全部主张是"对话"，所以第一秒不能是表单。**
v1 把 onboarding 做成了七屏向导——用户第一秒在填表，等于第一秒就否定了产品。
召唤必须**发生在对话流里**：它开口、它问、你答，中间没有跳页。

**② 模糊 → 具象 = 被理解的程度。**
守护神的形象不是加载动画，是**它懂你多少的直接映射**。
这是"懂的程度可视化为它的形态"的最省实现：一个模糊度参数就承载了整个隐喻，
不需要成长动画、不需要立绘。往后还能继续用（久不聊变淡、聊深了更亮）。

## 一、只有两个页面

| 页面 | 内容 | 状态 |
|---|---|---|
| **对话空间** | 日常的全部。顶部是它（随理解程度具象），下面是对话 | v1 |
| **串门** | 社交空间：引荐与到访 | v1 锁住 |

不要做成五个 tab 的 App。**别的东西全部收起来**。

**串门的锁由它自己解释**，不是"敬请期待"：

> "等我更懂你一点，我才知道该带你去见谁。急不来——见错人比不见人更糟。"

一句话同时完成三件事：解释为什么锁、暗示解锁条件（多聊）、预告野心。

> ⚠️ **解锁条件必须是"它懂你的程度"**，绝不能是连续登录天数或付费——挂钩登录会立刻把它变回打卡 App。
> ⚠️ **串门 ≠ 广场。** 是被引荐之后到某一个人的空间去，不是可浏览的用户列表。
> 一旦做成广场，用户会直接自己找人，守护神当场失去存在意义。**写进产品宪法。**

## 二、召唤（全程在对话里）

七个状态，都在同一个页面上发生：

```
未成形 → 寒暄 → 收生辰 → 成形中 → 首读 → 显形 → 命名 → 日常
 ▓▓▓░░   ▓▓░░░   ▓░░░░    ▒▒░░    ▒▒▒░   ▓▓▓▓   ████
（上排为具象度）
```

### 0 · 未成形

它先开口，压力在它那边。视觉上只有一团几乎看不见的光晕。名字位是「？」。

### 1 · 寒暄 → 要生辰

**这几句不是写死的台词，是一份任务规格。** 见 `SOUL.day1` 的「开场规格」。

要生辰的理由**必须当场成立，不能预设用户知道任何设定**：

- ✓ 「我还看不见你。报个生辰，我就能看见了。」——没有信息 → 看不见；给了信息 → 看得见
- ✗ 「我还不知道我是谁，这事得靠你」——缺一个前提（它由你的盘生成），新用户只会觉得莫名其妙

> **创世感不丢，只是延后**：等首读把人震住之后再翻牌——"我也是从这张盘里出来的"。
> **先钩住，再给神话。**

### 2 · 收生辰

三个字段内联在对话里，一次问一件，问完接一句话再问下一个。

> ⚠️ **「不确定」必须是显眼选项。** 大量中国人不知道自己几点出生，卡在这直接损失一半用户。
> 不确定 → 用**日柱主导**（日主不依赖时辰，性格底色照样推得出），并如实说明"知道的话我能更准"。

隐私说明**用它自己的话说在对话里**，不弹法律条款：

> "这个只用来把我生出来。不外传，你随时能看我知道你什么，也随时能全删。"

### 3 · 成形中

**证据是一句人话，不是一张排盘卡。**

- ✗ 四柱卡片（"乙亥 乙酉 丁巳 庚戌"）——对 95% 的人是零信息量，在**表演权威**而不传递内容，而且那正是每个算命 App 的做法
- ✓ 「**九月末，天刚黑透的时候。**」——从生辰推出，用户当场点头，术语一个没用

**术语在后台可查**：一个很轻的「看我是怎么算的 ›」，展开是完整四柱与推导。较真的玄学用户会点，普通用户不会注意。

同时具象度上升——**成形本身就是"有根据"的证据**，不需要再放一张卡片重复说一遍。

### 4 · 首读

整个产品最重要的几句话。规则见 `SOUL.day1`：必须硬、说处境不说预测、术语当场兑现成白话、具体到能被反驳。

分 3-4 条短消息发，最后一条落在一个眼下的小建议上。

### 5 · 显形（内联三选一）

- **候选每人独有**：从各自命盘的具体元素生成，**不是固定的三个原型**
- 名字用大白话（"一盏灯"，不是"灯灵"），各自写明出处，出处也用白话
- **选完锁定不可换**，稀缺感保留在选择之后
- 选定后整个界面的色相跟着变——它真的变成你选的那个

> ⚠️ **绝不硬映射。** 怕狗的抽到犬、巳时的抽到蛇、回族用户抽到猪——都是真实事故。**给选择就是保险。**

### 6 · 命名（名字归主人）

**它只问，不自称已有名字，也不暗示哪个更好。**

用户想不出来时才给备选让他挑。他起的任何名字都接受，哪怕很随便——**接受时也不夸"这名字真好"**。

### 7 · 进入日常

- 状态行「**在翻九月的天气 · 认识 1 天**」——前半必须来自它的**真实日记**，不能是随机文案
- 第一个问题要**只有他能答**：「刚才那段里哪句最不对？」远胜「今天过得怎么样」
- 账号绑定推到这之后，用它自己的话说

> ⚠️ **红线：「认识 N 天」是累计天数，不是连续天数。** 断了不清零、不提示、不惩罚。
> 做成打卡即违反 HARNESS L4「禁止依赖工程」——那正是我们批评竞品的地方。

## 二·五、信任怎么被看见（v1 就要有）

**机制存在 ≠ 用户信任。** 我们有窄接口、有隔离、有拒绝权——但用户看不见就等于没有。
所以要把机制变成**看得见的动作**：

| 时刻 | 它做什么 | 为什么有效 |
|---|---|---|
| 首读之后 | 主动指出自己最没把握的一处 | 主动暴露局限比全知全能可信，成本极低 |
| 被说"不对" | "行，那是我看错了"，不解释不圆场 | 会认错的才可信 |
| 随时 | 问"你都知道我什么"→ 立刻给清单 | 不是设置页里的条款，是一句话 |
| ⭐ v2·引荐期 | **"今天有个推荐我给你挡了，因为 X"** | **最强的一个**：损平台利、证明它站你这边。中心化撮合系统结构上做不出这个动作 |

> 串门锁着的理由是**双重**的：不只是密度不够，更是**信任还没到能替你出面的程度**。

## 三、语音（v1 即支持）

语音不是后加的功能，是**为数字人铺的路**，也是对话质感的试金石：
写字的 AI 味还能忍，**说话的 AI 味忍不了**。

| 项 | 规格 |
|---|---|
| 输入 | 按住/点击说话，STT 转文字后走同一条对话链路 |
| 输出 | TTS 朗读。**音色与语速由日主推导**（丁火温、庚金脆、壬水缓、戊土稳） |
| 长度 | 语音模式下**每次回复 ≤40 字、最多两句**，不分点、不排版 |
| 降级 | 不支持语音的环境自动退回纯文字，不报错、不阻断 |

> 语音模式的长度限制不是风格建议，是 harness 级约束——一段 300 字的 TTS 是灾难。

## 四、引荐与串门（v2，有第二个用户之后）

### 引荐前：先让用户看见"它会怎么介绍我"

引荐发生**之前**，用户必须能看到并直接编辑那张 `GuardianShareCard`——就是那三五行字。

> 这一步把抽象的隐私授权变成**具体的可编辑文本**。用户看到"夜猫子 / 独立游戏 / 不聊收入"，
> 立刻知道边界在哪——比任何隐私设置面板都有效。
>
> ⚠️ **推断 ≠ 授权**：它从聊天里"看出来"的东西（比如你在焦虑求职）**不得自动进卡片**。
> 每个字段必须可追溯到用户明确同意。推断出来的默认更敏感，不是更安全。

### 引荐卡片

- **会过期**（24 小时）。稀缺但不制造焦虑——过期就没了，**不做"你错过了"的提示**
- 内容：它用自己的话说为什么是这个人 + 对方的窄接口信息（`GuardianShareCard`）
- **绝不展示对方的私密内容**
- 两个按钮：**认识一下 / 这次算了**。选"算了"不问理由

### 双边同意 → 建房

两边都点了才建房。**任一方没点，另一方永远不知道曾经有过这张卡**——消除面子成本，这是敢不敢点的关键。

### 四方房间

- 成员：两个真人 + 两只守护神
- **目标是把他们聊到不需要我**。他们聊起来 → 守护神闭嘴；冷场 → 必须上（点名、递话、问只有对方能答的）
- **每条消息必须指向一个真人**，两只 agent 绝不互相搭腔
- 连续 3 次救场无回应 → 体面收尾

### 现场的披露边界

- 只说卡片里有的 + 主人自己在这个房间说过的
- **被追问卡片之外的事 → 把问题转给本人**：「这你得问他。」
  知道但不说，同时把球踢回真人——保密、推进对话、符合"每句话指向真人"，一举三得
- **不跟主人八卦对方**：对方卡片内容可转述并注明来源；房间里看到的对方私事，事后一个字不带回来。
  **忠诚如果不对称，用户迟早会想：它对别人是不是也这样？**

### 结束

**成功的样子是他们迁出去**（加微信、约见面）。产品要**主动提供这个出口**，不试图把人留在房间里。

**事后全文可查**：用户可以看到它在那个房间里说过的**每一句关于自己的话**。这是信任的最终兜底。

## 五、v1 明确不做

- 引荐与串门（没有第二个用户）
- 形态成长动画、专属空间可视化（先验证留存，再做重资产）
- 角色立绘、数字人（语音先行，形象后置）
- 社群、广场、动态流
- 任何积分 / 等级 / 打卡

> **v1 只需成立一件事**：一个人报了生辰，被第一读说中了，第二天还愿意回来跟它说话。
> 这件事不成立，引荐、匹配、网络效应全都不成立。

## 六、已实现对照（`../app/`）

| 设计决策 | 落在哪 |
|---|---|
| 召唤在对话里，无表单向导 | `public/app.js` 状态机 |
| 模糊→具象六档 | `app.js: resolve()`，选定形象后用其色相 |
| 「我还看不见你」开场 | `app.js: OPENERS` |
| 不确定时辰一等公民 | 前端按钮 → `bazi.js: hourKnown:false` |
| 证据是人话 | `bazi.js: describeMoment()` |
| 术语后台可查 | 「看我是怎么算的 ›」折叠卡片 |
| 形象候选每人独有 | `prompts.js: personaPrompt()` 由 LLM 从各自命盘生成 |
| 名字归主人 | `prompts.js: namingPrompt()` + `/api/naming` |
| 语音双向 + 长度约束 | `app.js: speak()` / `prompts.js: VOICE_MODE` |
| 串门锁着，锁由它解释 | `index.html .visit` |
