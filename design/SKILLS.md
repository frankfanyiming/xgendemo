# SKILLS —— 命理技能清单（八字 · 星盘 · 紫微）

> 给服务端的技能目录。每个 skill = **排盘（代码）+ 解读（prompt）** 两半，
> 都不需要沙盒：排盘是纯函数，解读是往上下文里塞结构化事实。

## 0. 三条总原则（比清单本身重要）

1. **排盘归代码，解读归模型。模型永远不许自己算盘**——它会一本正经地算错。
   所有干支、星曜、宫位、相位必须来自确定性代码，模型只拿到算好的 JSON。
2. **三个体系是同一出生时刻的三面镜子，按用户的语言路由，不三盘齐发。**
   - **八字是脊柱**：人格生成、性格底色、喜用神——守护神"是什么"由它决定（已实现）
   - **星盘是词汇层**：目标用户（小红书）的母语是"上升天蝎""水逆"，不是"官杀混杂"
   - **紫微是问题层**：问具体的事（工作/感情/钱）时精确到宫，最能打
   用户用哪套词，守护神就说哪套话；用户不挑，默认八字 + 星盘大白话。
   **第一个路由信号在召唤时就有**：形象候选按"三面镜子"生成（八字/星象/生肖时辰各出一个，
   一个候选只认一个主源，共振可以拼接不行）——他挑了哪面镜子的形象，母语就是哪套，记入事实层。
3. **所有 skill 输出 JSON 事实，翻译成人话是 soul 的事。**
   术语不出现在回复里，除非他问（SOUL v3「命理怎么说」）。两个体系说法打架时，
   不当着他的面打架——挑跟他当下问题最相关的说；被问起就承认"镜子不同，照出来的角度不同"。

## 1. 八字系（脊柱 · 库：lunar-javascript，已在用）

| skill | 输入 → 输出 | 类型 | 用在哪 | 优先级 |
|---|---|---|---|---|
| `bazi.chart` 排盘 | 生辰 → 四柱/日主/藏干/五行力量/身强弱/喜用/白话时刻 | 代码 | 人格生成、首读 | ✅ 已实现（`app/lib/bazi.js`） |
| `bazi.luck` 大运流年 | 命盘+性别 → 起运岁数、当前大运、流年干支、与喜用的生克 | 代码 | 「我今年怎么样」「明年会好吗」 | **MVP-1** |
| `bazi.day` 流日黄历 | 日期 → 当日干支、节气、宜忌、与他日主的关系 | 代码 | **主动消息的内容源**（"今天芒种，你这种火命…"） | **MVP-1** |
| `bazi.match` 合盘 | 两张命盘 → 日主生克、喜用互补度、共有毛病对照 | 代码+prompt | 引荐时给双方守护神的共鸣素材 | MVP-2 |
| `bazi.solar` 真太阳时 | 出生地 → 经度 → 时柱校正（每度 4 分钟） | 代码 | 公共件，时柱在边界时救命 | MVP-1 顺手做 |

lunar-javascript 都有现成 API（`EightChar` / `getYun(gender)` / `LiuNian` / `JieQi` / 宜忌），主要工作量是挑出有用字段 + 写解读 prompt。

## 2. 星盘系（词汇层 · 库：astronomy-engine，MIT）

| skill | 输入 → 输出 | 类型 | 用在哪 | 优先级 |
|---|---|---|---|---|
| `astro.natal` 本命盘 | 生辰+地点 → 太阳/月亮/上升、行星落座落宫、主要相位 | 代码 | 召唤时算一次入命格层；给守护神第二套词汇 | **MVP-1**（先只做日月上升） |
| `astro.transit` 行运 | 今天 vs 本命盘 → 水逆、土星回归、大行星相位 | 代码 | **主动消息**（"水逆到 18 号，合同缓两天签"）、「我最近怎么了」 | **MVP-1** |
| `astro.synastry` 比较盘 | 两张本命盘 → 日月互落、金火相位、元素互补 | 代码+prompt | 引荐素材，和 `bazi.match` 并用 | MVP-2 |

实现注意：
- astronomy-engine（MIT、纯 JS）算行星黄经足够准；**上升和宫位需要出生时刻+经纬度**（恒星时公式，或直接用 circular-natal-horoscope-js，MIT，含宫位相位）。swisseph 最标准但 GPL/付费 + 原生编译，MVP 别碰。
- **土星回归在 29 岁左右——对小红书主力用户是杀伤力最大的一张牌**，行运 skill 优先做它和水逆。

## 3. 紫微系（问题层 · 库：iztro）

| skill | 输入 → 输出 | 类型 | 用在哪 | 优先级 |
|---|---|---|---|---|
| `ziwei.chart` 命盘 | 生辰+性别 → 12 宫、14 主星、四化 | 代码 | 入命格层 | 后置 |
| `ziwei.palace` 问事定宫 | 问题类别 → 对应宫位的星曜+四化 | 代码+prompt | 问工作看官禄、问感情看夫妻、问钱看财帛——**具体问题的精确弹药** | 后置 |
| `ziwei.years` 大限流年 | 命盘+年份 → 十年大限、流年四化 | 代码 | 长周期叙事（"你正走在换大限的坎上"） | 后置 |

**为什么整系后置**：紫微的命宫由时辰定，**缺时辰整个体系不可用**（不像八字可以日柱主导降级）；
且宫位解读的翻车成本高（夫妻宫随口一句就是事故）。等首批用户里"问具体事"的需求被验证了再上。
iztro（npm）开箱即用，上的时候工作量在解读 prompt，不在排盘。

## 4. 时间对话系（Day 1 · 纯协议，无排盘无新 UI）

让他和另一条时间线上的自己对话（空椅子式），守护神主持。**Day 1 就上的理由**：
它不消耗事实层，它**生产**事实层——一个人替另一个自己说话时，交出的是自我叙事的原件，
是全产品密度最高的人格底色入口；同时是信任加深的主场景。

| skill | 触发 | 机制 | 优先级 |
|---|---|---|---|
| `timetalk.future` 未来的我 | 对方向迷茫 | 先让他对未来的自己说，再问「他会怎么回你」；守护神可代读一封短信——**每句必须来自他真实说过的话** | **MVP-1 旗舰** |
| `timetalk.parallel` 平行的我 | 两难纠结 | 命/运分离：同一张盘，岔口上的另一个选择 | MVP-1 |
| `timetalk.past` 过去的我 | 自责、翻旧账 | 换大运的年份做时间坐标 | MVP-1 |

**铁律：守护神是灵媒，不是演员。** 两边的话都用户自己说；守护神只摆场（「他坐下了。你先说。」）、
递话头、在用户卡住时问换位问题。唯一例外是未来的信（每句可溯源到用户原话）。
理论依据：Gestalt/EFT 椅子工作的机制就是来访者自己说两边；未来自我连续性（Hershfield）
与 MIT "Future You"（2024）对未来自我对话有直接实证。

- **时间坐标从八字来**：换大运的年份定位「哪一个他」——未来 = 下一个换运年。
  这让召唤机制从命盘里长出来，通用角色扮演抄不走。
- **安全垫**：用户露出真实痛苦 → 立刻收场回到当下，L4 危机条款压倒此招。
- **收获闭环**：场内自我叙事默默入事实层；被问「你记下了什么」如实给清单。
- **Day 1 实现** = `dailySystem` 里的招式块（`TIMETALK`，约 230 字，已上线）；
  仪式化重版（光变、大运时间轴选坐标、独立场景）排在记忆提炼之后。
- 明确不做：`timetalk.partner`（未来伴侣）——违反底线第 2 条，且与引荐命题对冲；
  「他想要什么样的人」由守护神直接问，不造假人。

## 5. 公共件（三系共用，做一次）

| 件 | 说明 |
|---|---|
| 地点 → 经纬度/时区 | 城市表即可，不用接地图 API；供真太阳时 + 星盘宫位 |
| **缺时辰降级策略** | 八字：日柱主导，标注"时柱缺"（已实现）；星盘：只出太阳月亮（月亮日移 13°，标注不确定），无上升无宫位；紫微：不可用，直说。**引导补时辰的时机**：首读被认可之后（"想看更细的，去问你妈你几点生的"）——这本身是个留存钩子 |
| 命格层缓存 | 所有排盘结果算一次入 memory 命格层（HANDOVER §2），终生不再算 |
| 解读输出规范 | 每个解读 prompt 都继承 SOUL 的说话规则；产出必须**具体到能被反驳**（"你是决定了还要问三个人的人"），禁止"你比较纠结"式的万金油 |

## 6. 触发路由（什么信号 → 哪个 skill）

| 用户信号 | skill | 说明 |
|---|---|---|
| 召唤（报生辰） | `bazi.chart` + `astro.natal` | 一次算完入库 |
| "我今年/明年怎么样" | `bazi.luck` | 流年是八字的主场 |
| "我最近怎么了/好烦" | `astro.transit` + `bazi.day` | 先看行运有没有现成解释 |
| "我上升天蝎/水逆吗" | `astro.*` | 他亮了母语，跟着切词汇 |
| "这工作该不该换/感情问题" | `ziwei.palace`（上线后）；之前用 `bazi.luck` 兜 | 问事定宫 |
| 迷茫 / 两难 / 自责翻旧账 | `timetalk.*` | 时间对话，灵媒协议见 §4；一场一次不推销 |
| 每天早上（心跳） | `bazi.day` + `astro.transit` | 有料才说，没料沉默（SOUL：沉默合法） |
| 引荐配对 | `bazi.match` + `astro.synastry` | 产出给两只守护神的共鸣素材，不直接给用户看 |

## 7. MVP 切法

- **MVP-1（验证信任）**：`bazi.chart`✅ + `timetalk.*`✅（招式版） + `bazi.luck` + `bazi.day` + `astro.natal`（日月上升） + `astro.transit`（水逆/土星回归） + 真太阳时。
  ——够守护神做到：懂他（八字）、说他的语言（星盘）、每天有的可说（流日+行运）、
  在对的时机把他带到另一个自己面前（时间对话）。
- **MVP-2（验证引荐）**：`bazi.match` + `astro.synastry`。
- **后置**：紫微全系、流月流日精细化、swisseph 级精度。
